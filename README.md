## 本地启动

在仓库根目录运行：

```bash
python3 -m http.server 4173
```

浏览器打开：

```text
http://127.0.0.1:4173/
```

首次在线打开后，应用外壳会被 Service Worker 缓存。Chrome/Edge 可使用浏览器的“安装应用”，iPhone 可使用 Safari“添加到主屏幕”。

## 品牌标准份食物库（v11）

本批收录 117 个唯一产品规格，不是所有品牌或完整在售菜单；161 条原有基础食物保留。默认展示中国大陆品牌数据。

| 品牌 | 地区 | 标准规格数 | 已公开数据 |
| --- | --- | ---: | --- |
| 麦当劳 | 中国大陆 | 72 | 热量、蛋白质、碳水、脂肪 |
| 赛百味 | 中国大陆 | 9 | 轻盈三明治与能量碗热量 |
| 瑞幸咖啡 | 中国大陆 | 21 | 指定杯型、冷热与糖奶配置热量 |
| 肯德基 | 中国台湾 | 7 | 热量、三大营养素、成品份重 |
| 汉堡王 | 中国台湾 | 8 | 热量、三大营养素 |

- 优先使用官方标准成品营养，而非编造未公开的原料克重。麦当劳官网每份 kJ 除以 4.184 换算 kcal 并取整，资料版本为 2025 年 4 月；其他品牌采用官方 kcal。各条目含来源 URL、资料版本、核对日期、标准配置和限制。核对日期不代表配方发布日期。
- 麦当劳饮料与早餐两个官网入口重复列出优品豆浆，导入原始资料保留 74 行，构建时去重为 72 个唯一规格。不同杯型独立记录。配方和在售状态可能变化，以购买地当前官方标示为准。
- 赛百味来自中国大陆官网公开索引，新版站点页面框架未能直接确认当前在售；未注明面包长度或重量，不擅自称作 6 英寸，也不适用于任意自选三明治。瑞幸“不另外加糖”不等于无糖，杯容量不当作成品克重。
- 肯德基与汉堡王台湾配方不能套用大陆同名产品，默认隐藏，需切换地区。尚未找到可核验的这两家大陆完整营养数据；本批不收录星巴克大陆或披萨品牌，不用第三方猜值填满菜单。
- 品牌食品 `basis: "serving"`，按份数记录（如 0.5 份），基础食物仍按每 100g 换算。所有重量缺失保持 `null`，不虚构每 100g 营养。历史字段 `grams` 在品牌记录中代表份数，由 `quantityUnit: "serving"` 区分；`foodSnapshot` 保留当时标准份数据，编辑按快照重算。
- 蛋白质、碳水、脂肪缺失保持 `null`，已知为 0 则保留 0。汇总显示已知小计与缺失标志，不把未知按 0；该餐剩余营养自动推荐暂停，但热量正常累计。按份品牌成品不参与按克自动配餐。
- 单份比例不能模拟拆掉面包、换奶或额外加料；套餐应逐项记录，额外油、酱料和饮料另记。无真实拍照识别功能。

来源事实位于 `research/*-products.json`；构建脚本 `node scripts/build-brand-library.mjs` 生成 `brand-data.js`。`node scripts/import-mcdonalds.mjs` 可重新从官网已链接菜单采集麦当劳每份表格（联网，无法确定规格的页面跳过并写入导入报告）；更新时须人工核对地区、口径和源站版本后再构建。单元测试：`node --test tests/*.test.cjs`。

## 当前边界

- 已支持个人热量估算：身高、体重、年龄和生理性别用于 Mifflin–St Jeor；可选体脂率用于去脂体重公式，并展示两者对照。自动模式有体脂用体脂法，无体脂用身高体重法，也可手动选法。体脂估计不一定更准。
- 在首页“调整餐次”中可选每天 1–6 餐，编辑餐名和比例，按所选日期保存，或从该日起设为默认。每日总目标不变；每餐显示热量／蛋白质／碳水／脂肪目标、已吃与剩余或超出。默认三餐 30%／35%／35%，比例可以平均分配或自定义（合计必须 100%）。
- 减少餐次／改名不删除或自动移动原食物，未在计划中的餐次单独展示并仍计入全天；记录可手动改到计划内。各餐营养目标随每日目标变化，按整数 kcal 和 0.1g 取整守恒。
- 每餐可生成食物组合与克数：以本餐剩余目标为默认，也能查看整餐目标。五套基础组合支持基础食物库搜索替换和手动改克数，替换后按对应食物的每 100g 营养重新估算整组，不按等克数替换，也不用生熟固定倍数。清楚标出生重、熟重、干重、可食部、沥干和液体克重。品牌成品按份另记。
- 推荐采用有份量上限的数值拟合，显示实际热量／蛋白质／碳水／脂肪及与目标的差额，无法完全匹配时不承诺达标；不生成维生素、矿物质或疾病营养处方，也不自动排查过敏。食材均需按安全方式处理烹调，额外油和调味另记。
- 推荐方案单独保存在本机，不计作已吃；确认后才批量加入本餐，并可逐项修改。整餐模式在已有记录时需再次确认，避免重复计入；汇总与正式记录使用相同舍入规则。
- 整餐与剩余量模式分别保存草稿；推荐自动保存只合并草稿字段，不覆写另一标签页的新饮食记录。入账前重新检查当前目标，变化时先重算、再请用户确认。巴西坚果因宏量拟合无法控制其硒摄入而不参与自动配量，仍可手动记录实际摄入（依据：[NIH 硒资料](https://ods.od.nih.gov/factsheets/Selenium-HealthProfessional/)）。
- 日常活动与每周训练次数、分钟共同用于粗略活动系数；此映射是工具假设，不是经过验证的个人消耗模型。减脂先取 15% 缺口，维持取 0%，最终取整到 50 kcal。保存资料或更新体重同步重算；每日总量可只分三餐。
- 未完善资料前，旧版／演示目标会明确标注，不会自动套用他人的健康数据。升级保留既有餐食和体重记录。只适用于健康成人估算，完整公式、来源和限制见页面“目标说明”。
- 已内置 161 条常用食物，营养数据来自 USDA FoodData Central Foundation Foods 2026-04 与 SR Legacy 2018-04。
- 食物数据随应用下载，可离线搜索，不需要在浏览器中保存第三方 API 密钥。
- 生重、熟重是独立数据条目，详情中的计量状态不可任意切换。例如白米（生）365 kcal/100g，白米饭（熟）130 kcal/100g。
- 今日餐次中的每条记录都可点击修改克数、移动到其他餐次或删除；保存时会自动重算营养。
- 拍照识别已暂时从导航和记录流程中移除，后续接入真实识别服务后再恢复。
- 数据保存在当前浏览器的 localStorage。清理浏览器站点数据会删除记录。

## 重新生成食物库

先从 FoodData Central 下载 Foundation Foods JSON 与 SR Legacy JSON，再运行：

```bash
node scripts/build-food-library.mjs \
  --foundation /path/to/Foundation.json \
  --sr /path/to/SR-Legacy.json
```

生成器会写入 `data.js`，保留每条食物的 FDC 编号、英文原始描述、营养数据版本与热量计算方式。
